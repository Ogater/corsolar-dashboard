# CorSolar

Панель мониторинга четырёх солнечных электростанций. Основные графики показывают фактическую мощность в кВт; локальный сценарий используется только как резерв до ответа API.

На экране показаны три уровня данных:

1. Генерация каждой СЭС до коррекции (`solar_generation_kw`) и после неё (`with_battery_total_output_kw`).
2. Сумма `solar_generation_kw` четырёх объектов в каждой точке таймлайна.
3. Сравнение суммарной генерации объектов до коррекции (красная линия) и после коррекции АКБ (чёрная линия).

Панель управления позволяет повторно запросить графики и передать endpoint параметры тучи и АКБ.

## Структура

```
src/
  main.js            точка входа: подключает стили и запускает приложение
  app.js             оркестратор: связывает данные, графики и интерфейс
  core/
    config.js        параметры сценария, палитра, настройки проигрывания
    utils.js         числа, время, поиск ближайшей точки
  data/
    api.js           запрос к backend и валидация ответа
    mapApiResponse.js приведение ответа API к рядам для графиков
    demoScenario.js  локальный генератор суточного профиля
    series.js        прореживание рядов
    stations.js      справочник станций
  charts/
    chartSetup.js    общие опции Chart.js и пресеты линий
    createCharts.js  фабрики трёх типов графиков
    cloudBandPlugin.js подсветка интервала тучи
    playback.js      проигрывание суток
  ui/
    template.js      разметка, разбитая по секциям экрана
    dashboard.js     обновление показателей
    cloudControls.js форма настройки облака
    batteryControls.js форма настройки АКБ
    icons.js         SVG-иконки
  styles/            index.css + файлы по блокам интерфейса
```

## Запуск

```bash
npm install
npm run dev
```

Для production-сборки:

```bash
npm run build
```

## Данные

Панель запрашивает данные из `GET /api/demo-solar-battery/compare` при открытии и затем раз в минуту. Параметры запроса находятся в `src/data/api.js`.

В локальной разработке запросы `/api` проходят через Vite-прокси, потому что backend не разрешает CORS для `localhost`. Настройка:

```env
VITE_API_BASE_URL=
API_PROXY_TARGET=https://dev.monitoring.cor-int.com
```

Для production сервер фронтенда также должен проксировать `/api` на backend. Альтернатива — разрешить домен фронтенда в CORS и указать его адрес через `VITE_API_BASE_URL`.

Для Vercel внешний rewrite уже настроен в `vercel.json`: запросы `/api/*` проксируются на `https://dev.monitoring.cor-int.com/api/*` без браузерного CORS.

Ответ за сутки может содержать 1440 минутных значений на каждую серию. Полный ответ обрабатывается приложением, а для отображения используется min/max-прореживание: до 720 точек для больших графиков и до 180 для спарклайнов в карточках станций. Оно сохраняет пики и провалы, включая момент прохождения тучи.

## Проигрывание суток

Линия рисуется по времени, а не по номеру открытой точки: головная точка интерполируется между соседями, поэтому фронт движется непрерывно и даёт 60 кадров в секунду вместо рывков на каждом узле сетки. Параметры — `playbackConfig` в `src/core/config.js`.

При недоступном API интерфейс остаётся на демонстрационном наборе и показывает статус `API НЕДОСТУПНО · ДЕМО-РЕЖИМ`.
